# Action -> Result Protocol

SmartCore Feishu text input must use one path:

```text
Feishu text
  -> NLU action parser
  -> ActionExecutor
  -> database CRUD
  -> structured Result
  -> reply writer
  -> Feishu API
```

The Feishu text handler must not route user text through legacy keyword command branches. Card callbacks remain separate because they operate on an existing confirmation operation.

## Action Input

The action executor accepts only JSON-like dictionaries:

```json
{
  "action": "create_event | query_event | update_event | delete_event",
  "source": "feishu",
  "raw_text": "今晚 9 点提醒我复习",
  "actor": {
    "platform": "feishu",
    "user_id": "ou_xxx",
    "chat_id": "oc_xxx"
  },
  "request": {
    "timezone": "Asia/Shanghai",
    "now": "2026-06-07T18:00:00+08:00"
  },
  "payload": {}
}
```

LLM output and selector output must not use database row ids as the user's query/update/delete handle. Candidate selection uses short opaque refs generated by the backend, such as `c1`, `c2`, and `c3`. The executor may resolve those refs internally, but ids must not be exposed as the semantic operation surface.

## Event Types

`event_type` is one of:

- `course`: a course block. Requires `start_at` and `end_at`; when `end_at` is omitted, default duration is one hour.
- `plan`: a planned block. Requires `start_at` and `end_at`; when `end_at` is omitted, default duration is one hour.
- `schedule`: a scheduled reminder item. Requires `start_at`; default reminders are 30 and 15 minutes before `start_at`.
- `deadline`: a due item. Requires `start_at`; default reminders are 30 and 15 minutes before `start_at`.

Legacy names `course_session`, `life_event`, and `assignment` are storage compatibility details only. They must not appear in new prompts, new Feishu action inputs, new Result payloads, or user-facing replies.

## Create Payloads

```json
{
  "event": {
    "event_type": "plan",
    "title": "复习劳动法律法规",
    "start_at": "2026-06-07T21:00:00+08:00",
    "end_at": null,
    "location": null,
    "notes": null
  }
}
```

For `schedule` and `deadline`, `reminders` may be omitted. The executor fills `[30, 15]`.

## Query Payloads

```json
{
  "filter": {
    "event_type": "all | course | plan | schedule | deadline",
    "status": ["pending", "active"],
    "time_range": {
      "start": "2026-06-07T18:00:00+08:00",
      "end": "2026-06-08T00:00:00+08:00"
    },
    "limit": 20
  },
  "semantic": {
    "target_description": "今晚的劳动法律法规考试"
  }
}
```

`keywords` and `target_description` are hints only. The DB query returns a compact candidate list; a second prompt may choose candidate refs from that list.

## Update Payloads

```json
{
  "selector": {
    "mode": "semantic_ref",
    "refs": ["c1"],
    "filter": {
      "event_type": "all",
      "time_range": {
        "start": "2026-06-07T18:00:00+08:00",
        "end": "2026-06-08T00:00:00+08:00"
      }
    },
    "target_description": "晚上的劳动法律法规考试"
  },
  "patch": {
    "start_at": "2026-06-07T22:00:00+08:00"
  }
}
```

## Delete Payloads

```json
{
  "selector": {
    "mode": "semantic_ref",
    "refs": ["c1", "c2"],
    "allow_multiple": true,
    "filter": {
      "event_type": "all"
    },
    "target_description": "今晚所有事情"
  }
}
```

## Result Output

Every executor call returns:

```json
{
  "ok": true,
  "action": "query_event",
  "status": "applied | pending_confirmation | failed | ambiguous | not_found",
  "message_code": "EVENTS_FOUND",
  "operation_id": null,
  "data": {},
  "errors": [],
  "debug": {
    "model_input": {},
    "db_result": {}
  }
}
```

The frontend logs page must expose `debug.model_input` and `debug.db_result` in collapsed details for each user sentence.
