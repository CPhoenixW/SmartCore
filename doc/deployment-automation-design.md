# SmartCore 一键部署设计

## 目标

- 一个命令完成 `main` 快进更新、镜像构建、容器切换和健康检查。
- 前端或 Python 依赖锁文件不变时，复用对应 Docker 依赖层。
- 依赖缓存丢失时仍按锁文件安装，不隐式升级。
- 上线失败时自动恢复上一镜像和上一代码版本。
- 发布前自动备份 SQLite，不修改或删除生产 volumes。

## 验收标准

1. `frontend/package-lock.json` 和 `requirements.lock` 纳入版本控制。
2. Dockerfile 先安装锁定依赖，再复制业务源码。
3. `scripts/deploy_prod.sh` 支持正常部署和 `--rollback`。
4. 同一时间只允许一个部署进程。
5. 生产工作区不干净、分支错误、不能快进或 Compose 配置无效时停止。
6. 部署前生成 SQLite 备份。
7. 新容器必须通过 `/healthz`；失败时恢复旧提交对应的镜像。
8. 脚本不输出 `.env`、令牌或其他密钥。

## 数据和 API 影响

- 不修改数据库结构、API 合约和前端交互。
- 数据迁移：无。
- 生产数据库仍位于 `deploy_smartcore-data` volume。
- 回滚只切换代码镜像，不回滚数据库，也不重写 Git 历史。

## 安全边界

- 脚本仅允许在 `/opt/smartcore` 的 `main` 分支执行。
- Git 更新只允许 `git merge --ff-only origin/main`。
- 不使用 `git reset --hard`，不删除 volumes。
- 锁文件必须随代码评审，依赖更新变为显式变更。

## 测试矩阵

| 场景 | 预期 |
| --- | --- |
| 锁文件不变，仅 Python 源码变化 | Python 依赖安装层命中缓存 |
| 锁文件不变，仅 Vue 源码变化 | npm 依赖安装层命中缓存 |
| 锁文件变化 | 仅对应依赖层重新安装 |
| 健康检查成功 | 新镜像继续运行并记录发布状态 |
| 健康检查失败 | 自动恢复旧镜像与旧代码引用 |
| 工作区有未提交文件 | 部署在拉取前停止 |
| 两次部署同时运行 | 第二次因文件锁停止 |

## 性能目标

- 仅 Python 代码变化时不执行第三方依赖解析和下载。
- 仅前端源码变化时不执行 `npm ci`。
- 不要求请求路径性能测试，因为本次不改变运行时请求逻辑。
