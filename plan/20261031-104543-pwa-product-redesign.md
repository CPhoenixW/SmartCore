# SmartCore 顶尖手机 PWA 重构计划

## 目标与已确认决策

SmartCore 的主要用户是本人，主要入口是手机 PWA。下一版要把 PWA 从“桌面工作台的移动缩小版”改成“个人行动入口”：打开后立刻知道今天要做什么，可以用助手完成查询和记录，并能回看自己的助手历史。

已确认的产品决策：

- 手机主导航固定为：**总览、助手、日程、设置**。
- 不保留独立的全局搜索栏；搜索能力只放在助手中，由助手理解自然语言并查询事项、课程、DDL、计划、提醒和灵感。
- 助手会话保存到 Server，跨刷新、跨浏览器和跨设备可回看，并支持在助手内搜索历史消息。
- PWA 是唯一默认交互入口；飞书不回到主链路，DSH 继续作为助手运行时。
- Tailscale/Mac 控制仍属于下一阶段，本轮不扩大到电脑控制。
- 继续使用候选环境 -> 生产晋升、数据库备份和可回滚镜像流程；本轮不会删除现有事项或提醒数据。

## 现状证据

- `frontend/src/layouts/WorkLayout.vue` 仍提供顶部全局搜索，提交后跳转到 `/work/update?q=...`。
- `UpdateEventView.vue` 的查询键带有当天日期，后端虽支持不带日期的文本查询，但当前前端把搜索限制在单日事项，且不覆盖 Idea、助手消息或通知历史。
- `AssistantView.vue` 只把最近消息写进浏览器 `localStorage`；Server 没有助手会话和消息实体，无法跨设备回看或搜索。
- `msgLog` 是旧消息审计/兼容表，不表达 PWA 助手会话，不能直接当作聊天历史使用。
- 当前首页仍混合天气、设备、灵感、DDL、快捷入口等桌面模块；移动端导航虽然已减少，但信息层级仍以“完整后台”为中心。
- DSH SSE 已能提供状态、工具进度和最终答案；这部分保留并与新的会话持久化层对接。

## 产品信息架构

### 总览

总览回答三个问题：现在是什么时间、今天最重要的事是什么、接下来有哪些事。默认只展示：

1. Server 时间与当前日期；
2. 今日待办/课程/提醒，按时间排序；
3. 接下来 72 小时内的 DDL 和高优先级事项；
4. 一个“快速告诉助手”输入框和一个明显的新增入口；
5. 需要处理的收件提示（未处理灵感、失败通知或待确认操作）。

天气、设备状态、灵感详情、调试日志和课程维护不再占据总览首屏；需要时从设置或日程的二级入口进入。

### 助手

助手是手机端的主要工作入口：

- 首屏显示最近会话和“新会话”；
- 会话页保留现有 SSE 状态体验：承接、理解、查询/修改、整理、完成；
- 提供助手内搜索入口，搜索用户消息和助手回复；
- 搜索结果显示会话标题、命中摘要和时间，点击后定位到对应消息；
- 快捷建议只提供少量高频动作，如“今天安排”“记录一个待办”“查最近 DDL”；
- 用户明确提交的消息和助手最终回复保存到 Server；内部工具参数、scope、原始推理不保存到聊天历史。

### 日程

日程统一承载课程、计划、DDL 和提醒：

- 默认进入今天；可切换周视图和未来 72 小时；
- 日程卡片支持完成、取消、查看详情和跳转到编辑；
- 新增事项通过浮动按钮或助手完成，不再需要把“添加”单独占一个底部导航位；
- 课程维护、DDL 计划编辑等复杂表单保留，但从日程的二级入口进入。

### 设置

设置承担所有低频和系统级操作：

- 通知授权与推送状态；
- 账户、语言、时区和会话管理；
- 课程维护、灵感、设备、日志、屏幕和高级诊断入口；
- 显示助手运行状态和服务健康摘要，不把调试信息放在首页。

## 会话与搜索设计

新增 owner-scoped 的助手会话和消息模型，建议最小字段：

- `assistantConversation`: `conversationId`, `userId`, `title`, `createdAt`, `updatedAt`, `lastMessageAt`, `stat`；
- `assistantMessage`: `messageId`, `conversationId`, `userId`, `role`, `text`, `createdAt`, `clientMessageId`, `stat`；
- `(userId, updatedAt)`、`(conversationId, createdAt)` 和幂等键建立索引。

搜索使用助手专用接口，不再恢复顶部全局搜索。第一版采用 owner-scoped 的限量文本查询，保证中文短语和跨日期片段都能稳定命中；消息量显著增长后再引入经过实测的分词索引。搜索结果必须：

- 只能返回当前用户自己的会话和消息；
- 默认按相关性和最近时间排序；
- 有结果、无结果、网络失败和超长输入都有明确状态；
- 点击结果可以恢复会话并滚动到命中消息。

会话 API 计划包括：

- `GET /api/assistant/conversations`：最近会话和助手内搜索；
- `POST /api/assistant/conversations`：新建会话（也允许流式请求自动创建）；
- `GET /api/assistant/conversations/{id}`：读取会话消息；
- `POST /api/assistant/stream`：增加 `conversationId`，在流式生命周期中幂等保存用户消息和最终助手回复；
- 必要的归档/删除接口只在设置中提供，默认不做物理删除。

现有浏览器 `localStorage` 历史不直接丢弃：升级后提供一次性的“导入本机历史”动作，导入时重新绑定当前用户并使用客户端消息 ID 去重；用户不导入时不上传旧内容。

## 前端改造

- 移除顶部无效全局搜索输入和桌面式 API 状态胶囊；顶栏只保留当前页面标题、通知入口和账户入口。
- 底部导航只渲染四项：总览、助手、日程、设置；当前页面有明显选中态和安全区适配。
- 将设备、日志、灵感、课程维护、通知诊断等迁入设置分组；不删除现有路由，旧链接继续可用。
- 重做总览为单列优先的行动流，减少卡片数量、滚动嵌套和重复快捷入口。
- 重做助手为“会话列表/搜索 + 会话详情”两层结构，手机上输入框固定在底部，工具状态不遮挡正文。
- 重做日程为今天/周/72 小时三个视图，统一事项类型颜色和操作；复杂编辑在二级页面打开。
- 设置页显示通知、账户、服务状态和低频模块入口，避免把低频能力塞入导航。
- 处理加载、空态、错误、离线、重新连接、权限失效和长文本等状态；所有主要触控目标至少 44px。

## 后端与 DSH 改造

- 新增会话/消息 schema 与启动迁移，只追加表和索引，不改写现有事项、课程、DDL、提醒或通知数据。
- 新增会话查询、读取和搜索 API，所有 userId 从浏览器 session 派生，忽略调用方的 owner 字段。
- `assistant_stream` 接收并校验 `conversationId`，用户消息在发起 DSH 前保存，最终助手答案在 `done` 后保存；失败状态可重试且不产生重复消息。
- DSH session ID 与 SmartCore `conversationId` 稳定映射，保留现有工具 scope 和时间注入，不保存工具原始输出到用户聊天。
- 增加会话 owner isolation、幂等、断线重试、搜索权限和迁移测试。
- 不增加新的模型、机器人渠道或电脑控制能力。

## 验收标准

### 产品路径

- 手机打开 PWA 后，底部只看到“总览、助手、日程、设置”；不出现独立全局搜索框。
- 总览在一屏内能看到今日关键安排、下一项行动和快速呼叫助手入口。
- 助手可以新建会话、发送请求、看到状态和最终回复；刷新页面后仍能看到历史。
- 在助手内搜索关键词、日期或自然语言片段，可以找到跨日期的用户消息和助手回复，并打开原会话。
- 日程能查看并操作课程、计划、DDL、提醒；新增事项可通过助手或浮动入口完成。
- 设置能开启/关闭通知并访问低频模块，现有旧路由仍可打开。

### 工程与安全

- 会话和消息严格 owner-scoped；跨用户读取、搜索、更新和删除均被拒绝。
- 同一个 `clientMessageId` 重试不会产生重复用户消息或助手回复。
- DSH 超时、断线或错误时，用户能看到失败状态并重试，历史不会出现伪造的成功答案。
- 搜索查询有长度和结果上限，并始终使用相同 owner 约束；当前实现不依赖 SQLite 可选的 FTS5 扩展。
- 旧同步 `/api/assistant/message` 继续兼容，或在前端迁移完成后明确标记为兼容接口；不影响现有 DSH 工具契约。
- 数据库迁移可重复执行，候选与生产启动健康检查通过，生产发布前自动备份。

### 质量与性能

- 后端新增会话、搜索、迁移、权限、幂等和流式保存测试；前端新增四项导航、助手历史、搜索结果、错误/空态和移动布局测试。
- `.venv/bin/pytest -q`、`.venv/bin/ruff check app/server tests`、前端 Vitest、类型检查和构建全部通过。
- 个人规模下助手历史搜索 p95 目标小于 300ms（预置 10,000 条消息的测试数据）；SSE 首个本地状态事件小于 1 秒，最终答案延迟不变。
- 候选环境执行真实登录、跨日期搜索、会话恢复和助手请求；生产只复用通过验证的镜像，不做压力测试。

## 范围外与风险

- Tailscale/Mac 读取和执行控制延期，不因本次 PWA 重构提前开放 shell 或文件能力。
- 不在本轮重写后台业务、删除兼容表或清理旧路由；只重组手机入口并增加会话持久化。
- 会话历史包含个人内容，必须受现有 session、数据库备份和访问日志约束；设置中提供归档/删除，避免默认丢失。
- 自动导入 `localStorage` 历史存在重复和陈旧风险，因此默认不上传，必须由用户主动触发。
- PWA 推送仍依赖浏览器授权；通知失败不影响会话和日程。

## 交付与回滚

- 先在本地完成迁移、API、前端和测试；再构建候选环境并做真实用户路径验证。
- 通过候选后沿用 `promote_prod.sh`，部署前备份 SQLite；不直接编辑生产代码或数据库。
- 回滚优先恢复上一版本镜像；新增表保留，不删除数据，旧版本忽略新增表即可启动。
- 代码、文档、迁移和测试形成一个可审查 PR；没有通过验收前不合并、不发布。
